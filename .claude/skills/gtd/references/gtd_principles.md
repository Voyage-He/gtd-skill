# GTD 核心原则参考

## 收集 (Capture)

**原则**：大脑是用来产生想法的，不是用来存储想法的。

- 任何吸引注意力的事情都记录下来
- 使用最少的工具（越少越好）
- 快速捕获，不做判断
- 定期清空收集箱

## 理清 (Clarify)

对每个收集的条目，问：

1. **这是什么？** - 明确实际内容
2. **可操作吗？**
   - 否：垃圾、参考资料、将来/也许
   - 是：继续下一步

## 组织 (Organize)

### 决策树

```
这个可操作吗？
├── 否
│   ├── 垃圾 → 丢弃
│   ├── 参考资料 → 存档
│   └── 将来也许 → 放入someday_maybe.md
└── 是
    ├── 多步骤吗？
    │   ├── 是 → 创建项目
    │   └── 否 → 单条行动
    ├── 2分钟内能完成？
    │   ├── 是 → 立即做
    │   └── 否 → 委派或延期
    ├── 委派给他人？
    │   ├── 是 → 放入waiting_for.md
    │   └── 否 → 放入next_actions.md
    └── 有明确时间？
        ├── 是 → 放入calendar.md
        └── 否 → 放入next_actions.md
```

## 回顾 (Reflect)

**每周回顾清单**：

1. **收集** - 收集散落的笔记、想法
2. **处理** - 清空收集箱
3. **回顾** - 检查过去一周的日历
4. **回顾** - 检查未来1-2周的日历
5. **回顾** - 检查项目清单
6. **回顾** - 检查下一步行动清单
7. **回顾** - 检查等待清单（是否需要跟进）
8. **回顾** - 检查将来/也许清单
9. **回顾** - 检查参考资料
10. **创意** - 有什么新想法要捕捉？

## 执行 (Engage)

**四象限筛选**：

1. **情境** - 当前可用工具/地点
2. **时间** - 可用时间
3. **精力** - 当前精力水平
4. **优先级** - 重要性

## 项目定义

项目 = 任何需要多步骤、想在一年内完成的事项。

每个项目必须有：
- 清晰的成功结果
- 至少一个下一步行动
- 定期回顾

## 自然式计划

1. **定义目标和原则** - 为什么做？边界是什么？
2. **愿景** - 完成是什么样？
3. **头脑风暴** - 关于这个想法的一切
4. **组织** - 分类、排序
5. **下一步行动** - 明确第一步

## 常见问题

**收集箱满了怎么办？**
→ 立即安排时间处理，优先级高于其他工作

**项目太多？**
→ 评估是否都是真正的项目，有些可能只是单条行动

**下一步行动不清晰？**
→ 确保使用动词开头，描述具体可执行的动作

**总是忘记回顾？**
→ 设置固定的周回顾时间，添加到日历
